# Data

During development, GOBLIN-Spatial keeps the core working input datasets directly in the GitHub repository so that the package can be developed and tested without a separate data-deposit step.

The data are organised by scientific module rather than by the historical script number.

```text
data/
├── raw/
│   ├── cattle/
│   ├── sheep/
│   └── land/
├── controls/
├── interim/      # generated, ignored by Git
└── processed/    # generated, ignored by Git
```

## `data/raw/cattle/`

Contains the fixed 2020 ED agricultural/cattle baseline and the annual county cattle controls used to reconstruct the 2015-2025 ED cattle panel.

CSV sources may be stored as `.csv.xz`. Pandas reads these files directly with compression inference, so no manual unpacking is required.

## `data/raw/sheep/`

Contains the county and regional sheep controls, the combined sheep source/audit workbook, and the DAFM county sheep breed-composition anchors for 2016, 2020, 2022 and 2025.

The DAFM anchor ZIP contains one canonical CSV and can be read directly by pandas. The annual 2015-2025 county composition table is generated by the sheep module from these observed anchor years. It is therefore an intermediate product, not a second raw source file.

## `data/raw/land/`

Contains the AQA06 annual regional land-use controls used to reconstruct ED land trajectories around the fixed 2020 ED anchor.

## `data/controls/`

Small, auditable files that are part of the package logic are versioned here. Current examples are:

- `cohort2012-2020.csv`, the GOBLIN cohort relationships used for cattle and sheep biological disaggregation;
- `06_SE_Data_Controls.csv`, the official structural and holder-age controls used by the SE module;
- `county_region_map.csv`, the Irish county-to-region mapping used by the land/sheep hierarchy.

## Current core build inputs

The complete core external input inventory for the current Ireland 2015-2025 baseline is recorded in the repository-root `data_manifest.yaml`. That manifest is the authoritative list of files that a clean package build expects.

## Generated data

`data/interim/` and `data/processed/` are generated by the package and are not committed as working source data. The final clean data products can later be attached to a formal release and/or archived on Zenodo.

## Development versus release architecture

Keeping these compact inputs in GitHub is a deliberate development choice. If future source files become large, binary-heavy, or unsuitable for Git versioning, the same `data_manifest.yaml` can be changed to point to Zenodo or an official source URL without changing the cattle, sheep, land or SE scientific module interfaces.

## 2020 principle

The 2020 CSO Electoral Division agricultural baseline is the fixed fine-scale spatial anchor. Coarser annual statistics are used as temporal controls around that baseline rather than to overwrite it.
