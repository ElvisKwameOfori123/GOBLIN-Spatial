# Data

During development, GOBLIN-Spatial keeps the core working input datasets directly in the GitHub repository so that the package can be developed and tested without a separate data-deposit step.

The data are organised by scientific module rather than by the historical script number.

```text
data/
├── raw/
│   ├── cattle/
│   ├── sheep/
│   └── land/
├── controls/
├── interim/      # generated, ignored by Git
└── processed/    # generated, ignored by Git
```

## `data/raw/cattle/`

Contains the fixed 2020 ED agricultural/cattle baseline and the annual county cattle controls used to reconstruct the 2015-2025 ED cattle panel.

CSV sources may be stored as `.csv.xz`. Pandas reads these files directly with compression inference, so no manual unpacking is required.

## `data/raw/sheep/`

Contains the county and regional sheep controls and the combined sheep workbook used by the validated region-to-county-to-ED hierarchy. DAFM sheep composition inputs are kept in the same module folder as they are migrated into the modular implementation.

## `data/raw/land/`

Contains the AQA06 annual regional land-use controls used to reconstruct ED land trajectories around the fixed 2020 ED anchor.

## `data/controls/`

Small, auditable files that are part of the package logic are versioned here. Current examples are:

- `cohort2012-2020.csv`, the GOBLIN cohort relationships used for cattle and sheep biological disaggregation;
- `06_SE_Data_Controls.csv`, the official structural and holder-age controls used by the SE module;
- `county_region_map.csv`, the Irish county-to-region mapping used by the land/sheep hierarchy.

## Generated data

`data/interim/` and `data/processed/` are generated by the package and remain outside Git history. The final clean workbook and analysis-ready CSVs are therefore reproducible outputs rather than hand-maintained source files.

## 2020 principle

The 2020 CSO Electoral Division agricultural baseline is the fixed fine-scale spatial anchor. Coarser annual statistics provide temporal controls around that baseline rather than replacing it.

## Future public release

If the data bundle grows substantially, the same folder structure can later be backed by Zenodo or official download URLs while retaining the package API and checksum manifest. For now, the small working inputs are kept in GitHub to make development straightforward.
